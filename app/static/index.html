How matching works

Matching is deterministic: the same input always gives the same result. Scores come from string similarity rules, not from a trained model, and they are not probabilities.

The rule scale

Every metadata candidate gets a score from 0 to 100. Its position on this scale decides its classification.

08095
High confidence
Score 95 or higher. The row counts as matched.
Review
Score from 80 to below 95. A plausible candidate that a person should confirm.
No match
Below 80, or rejected by a rule. Not returned as a candidate; the row is unmatched.

ISRC Identifier match

If the input has a valid ISRC that exists in the reference catalog, that recording is returned directly with score 100, and artist and title are not compared. If the ISRC is missing or not in the catalog, matching falls back to metadata. It's only as reliable as the ISRCs in your data.

Metadata Artist and title match

Artist and title are normalized, then compared with RapidFuzz (fuzz.ratio). The score is 40% artist similarity plus 60% title similarity. A candidate is accepted only if the artist similarity is at least 60, the title similarity at least 92 and the weighted score at least 80.

Pipeline

  1. ISRC lookup. Exact identifier match in the reference catalog, if an ISRC was given.
  2. Normalization. Lowercase, Latin accents folded, punctuation removed, whitespace collapsed, title noise removed.
  3. Candidate retrieval. PostgreSQL's pg_trgm returns up to 100 reference tracks whose normalized artist or title has a trigram similarity of at least 0.3.
  4. Scoring. Each candidate gets a RapidFuzz similarity for artist and for title, weighted 40% / 60%.
  5. Rules. The minimum artist, title and weighted scores, plus the version check below.
  6. Classification. Accepted candidates are labelled by score and sorted best first.

Rules that prevent false matches

  • Version check. Remix, live, acoustic, instrumental, radio edit, extended mix, remastered, sped up and slowed versions never match a different version.
  • Title noise is removed. "Official Audio", "Official Video", "Official Music Video", "Lyric Video" and "Lyrics" are ignored when comparing titles.
  • Unicode aware. Latin accents are folded (Beyoncé → beyonce); other scripts such as Cyrillic or Japanese are kept, not discarded.
  • Empty metadata never matches. Inputs like "!!!" are rejected during validation.

Rules, not machine learning

There is no trained model. Normalization, retrieval, scoring and thresholds are fixed rules, so the same input against the same catalog always gives the same result, and every decision can be explained from the score and the rules above. A score of 95 means 95 out of 100 string similarity under these rules, not a 95% probability that two records are the same recording.

Matching only knows the reference catalog in the connected database. Unmatched means no reference track passed the rules; it does not mean the recording doesn't exist elsewhere.

Add reference track

Creates a permanent reference record in the database this application is connected to. It becomes a match candidate for every future search. Records can't be edited or deleted from this interface. Duplicate ISRCs and duplicate normalized artist + title are rejected.
